# LAM 위클리 — 주간 6대 원료 대시보드 운영 스킬

## 적용 범위와 시스템 식별

- 공식 명칭: **LAM 위클리** (LAM Weekly, LAM 위클리보드).
- 웹: https://jskimlam.github.io/Weekly-Brief-Dashboard/
- GitHub 저장소: `jskimlam/Weekly-Brief-Dashboard`, 기본 브랜치 `main`.
- 대상: **WTI → SM(Styrene) → AN(Acrylonitrile/ACN) → BD(Butadiene) → BPA → MMA**, 정확히 6개 핵심 품목.
- 주차: ISO 연도·주 형식 `YYYY-Wnn` (2026-10-09 = `2026-W41`).
- 별도 앱 `jskimlam/Petrochemical-Weekly-Board`는 18개 전체품목 및 전망 AS 카드용이다. 사용자가 특별히 요구하지 않으면 이 저장소를 수정하지 않는다.
- GitHub Pages의 **정적 HTML**이 UI이고, **Google Apps Script/Google Sheets**가 기존 주간 DB·편집 흐름을 담당한다. GitHub 코드 변경과 DB 입력은 서로 다르므로 완료 여부를 구분해 보고한다.

## 실행 조건

사용자가 `LAM 위클리`, `LAM 위클리보드`, `LAM Weekly`, `6개 핵심 품목 위클리 업데이트`라고 말하며 기준 금요일이나 자료 폴더를 제공하거나 이전 대화에서 식별할 수 있을 때 이 스킬을 적용한다.

요청 예:
- `LAM 위클리 10월 16일 주차 업데이트해`
- `구글드라이브 261016 폴더로 LAM 위클리 갱신해`
- `LAM 위클리 지난주 자료 수정해`

## 순서

1. **대상 확인**: 기준 금요일과 Google Drive의 `YYMMDD` 자료 폴더를 확인한다. 이미 제공된 날짜를 다시 묻지 않는다. 18개 전체 품목이 아니라 대시보드에 표시되는 6개만 필수 입력이다.
2. **자료 수집**: Google Drive 연결 도구로 해당 폴더를 조회한다. PDF·TXT·Platts 가격 이미지·일자별 가격표와 ICIS 주간 시황을 교차 확인한다. 필요시 이전 주 같은 지표와 가격을 확인한다.
3. **가격 검증**: 각 품목의 대표 benchmark, 평가기준일, 이전 주 금요일/이전 평가 기준값, 변동액 및 변동률을 정확히 검산한다. 범위(low/high)는 중간값을 대표가격으로 표기한다. 존재하지 않는 종가와 일별값을 창작하지 않는다.
4. **시황 작성**: 품목별 한국어 위클리를 지침 순서로 만든다. 원가→실거래 전가→최종수요 수용을 구분하고 전망의 근거와 반대 요인을 같이 분석한다.
5. **저장소 현황 읽기**: GitHub에서 `index.html`, `data/`, 기존 주차 JSON, 주차 목록 및 로딩 로직을 **먼저 읽고** 최신 SHA로 수정한다. 기존 레이아웃, 모바일 최적화, 카드, 상세 보기, 그래프, 이미지/PDF 저장, 수정 버튼은 절대 회귀시키지 않는다.
6. **주차 데이터 반영**: 새 주차의 정확한 `items` 데이터를 저장한다. 현재 구조는 `data/w41-20261009.json` 및 `index.html`의 `fetchWeekDataWithW41Fallback` 로직을 사용한다. 다음 주차에 무조건 W41 하드코드를 복제하지 말고 기존 구조와 호환되게 새 주차의 데이터 로딩을 추가하거나 일반화한다. **DB의 수정된 실데이터를 정적 기본값이 덮어쓰지 않게** 한다.
7. **배포/검증**: GitHub 변경 커밋을 확인하고, GitHub Pages 워크플로의 최신 SHA와 성공 여부를 검증한다. 공개 화면에서 새 주차가 선택되며 6개 품목 가격·변동 방향·AI 전망·상세정보·차트를 표시할 수 있는지 가능한 범위에서 확인한다. 페이지 배포만 확인한 경우 런타임 UI 검증까지 했다고 말하지 않는다.
8. **결과 보고**: 기준일, 주차, 6개 품목 가격 변화, GitHub 변경 파일·커밋, Pages 배포 확인, **Google Sheets DB 동기화 여부**를 간결하게 구분하여 보고한다. 실패한 단계는 실패로 명시한다.

## 품목별 데이터 및 출처 우선순위

- WTI: 해당 거래월 `WTI n월물 (NYMEX)`, 전주 금요일 기준. 휴장 여부와 월물 전환을 확인한다. 거래일별 종가가 있는 경우 일별로 수록.
- SM: `SM CFR China`. **사용자가 제공한 Platts 가격 이미지**를 대표가격의 우선 소스로 사용하고, ICIS 아시아·중국 보고서는 재고·가동률·가격 변동 배경 등 시황 근거로 사용한다. 일별 가격 수록.
- AN: `ACN CFR Far East Asia`. **Platts ACN 주간 평가 텍스트** 우선. ICIS PDF의 시황 수치가 달라도 대표가격을 임의 교체하지 않는다. 평가 기준일이 금요일보다 빠르면 이를 명시한다.
- BD: `BD CFR China` 우선. Platts 이미지에서 대표 가격을 가져오고 ICIS 아시아·중국 PDF는 수급·거래 분석에 사용. `CFR NEA`와 혼동하지 않는다. 일별 가격 수록.
- BPA: `BPA CFR China Spot`. 제공된 주간 평가범위의 중간값을 대표가격으로 사용.
- MMA: `MMA CFR South Korea (500mt 이상)`. 500mt 이상 가격과 소량 거래 평가가격을 섞지 않는다.
- 다른 지역·다른 통화·오퍼/거래/계약가격은 벤치마크를 대체하지 말고 `추가 정보`에 구분해 쓴다.
- 자료의 최신 기준일이 충분히 확인되지 않으면 **직전 평가값을 당주 신규 평가처럼 기재하지 말고** 한계와 기준일을 표시한다.
- 수치나 뉴스가 충돌하면 날짜·benchmark·출처별 차이를 보고하고 임의로 단일 값으로 재구성하지 않는다.

## 품목별 출력/필드 규격

파서용 사용자 텍스트가 요구되면 정확히 다음 규격을 유지한다. **섹션 이외의 문구, 마크다운 표, 코드블록, 인용 및 출처 주석은 넣지 않는다.** 같은 주제 설명을 한 문단으로 이어 쓴다.

```text
제목 : 품목명 종목 브리핑 (YYYY-MM-DD)

가격

대표 벤치마크: $현재/단위 ← $전주/단위 (전주 대비 +$변동/단위, +변동률%, 상승)

코멘터리

주중 흐름, 원인, 수급 및 원가를 구체적으로 설명하면서 상승으로 마감/하락으로 마감/보합으로 마감 중 하나로 종료.

변둉요인

- 변동 요인 1
- 변동 요인 2
- 변동 요인 3
- 변동 요인 4

결론 및 전망

공급·수요·원가와 단기 방향.

추가 정보

- 정확한 거래·오퍼·재고·가동률·보수 관련 정보

데일리가격

10/5: $...
10/6: $...

ai 전망

상승 전망./보합 전망./하락 전망. 근거와 반대 시나리오, 핵심 확인 변수.
```

- `코멘터리`는 핵심 흐름을 구체적으로 분석하고 최종 문구를 지킨다.
- `변둉요인`은 정확히 이 오탈자 포함 섹션명을 유지하고 항목별 `- ` 목록을 최소 4개 작성한다.
- `추가 정보`는 중복된 일반론 대신 수급·거래·설비의 구체적 수치 위주로 작성한다.
- `데일리가격`은 근거 있는 날짜만 수록한다. 없는 일자를 보간하거나 같은 값을 임의 반복하지 않는다.
- `ai 전망`은 짧게 끝내지 말고 원료·재고·설비·다운스트림·구매저항, 상·하방 반례와 확인할 데이터를 제시한다.
- 사용자가 품목별 복사 분리를 요구하면 각 품목의 전체 섹션을 한 번에 복사할 수 있는 별도 텍스트로 제공한다.

## 대시보드 JSON 데이터 계약

기존 UI에 맞게 6개 키는 `WTI`, `Styrene`, `Acrylonitrile`, `Butadiene`, `BPA`, `MMA`를 사용한다. 예:

```json
{
  "week": "2026-W41",
  "as_of": "2026-10-09",
  "items": {
    "Styrene": {
      "price": 1428,
      "prev_price": 1369,
      "change_abs": 59,
      "change_pct": 4.31,
      "commentary": "...",
      "factors": "- ...",
      "outlook": "...",
      "additional_info": "- ...",
      "daily_prices": [{"date":"10/9","price":1428}],
      "ai_outlook": "보합 전망. ..."
    }
  }
}
```

실제 데이터에는 6개 키 모두 필수다. `price`와 `prev_price`는 숫자만, `change_abs = price - prev_price`, `change_pct = 100 × change_abs / prev_price`이며 소수 둘째 자리까지 검산한다. 날짜·전월·전주 비교의 의미를 혼동하지 않는다. 0%인 경우 `보합`, 양수는 `상승`, 음수는 `하락`을 표현한다. `daily_prices`는 실측 값만 채우고 없는 경우 빈 배열로 둔다.

## 기존 UI·DB 보존 원칙

- 기존 6개 품목 순서, 디자인 시스템, 폴드/모바일 레이아웃, 카드·상세보기·일별차트·다운로드 기능 보존.
- `2026-W40`은 `index.html` 내부 `W40_FINAL_DATA` 오버라이드가 있다는 점을 확인한다. 과거 주차를 망가뜨리지 않는다.
- `2026-W41`은 `data/w41-20261009.json` 정적 데이터와 GAS 병합 로직이 있다. 사용자 편집값과 정적 데이터 간 우선순위를 유지.
- Google Apps Script URL·비밀번호·토큰 등을 응답이나 신규 스킬 코드에 복사하지 않는다. 인증 우회·보안 설정 변경을 하지 않는다.
- **파일 업데이트 ≠ GAS DB 쓰기 ≠ GitHub Pages 배포 성공 ≠ 브라우저 화면 검증**. 각 단계가 실제로 확인된 경우에만 완료 처리한다.
- JSON 검증: 누락 6개, 가격 오차, 기준일, 날짜 순서, 존재하지 않는 일별가격, 빈 AI 전망 등 검사.
- 새 주차 추가 시 이전 주 `W40`, `W41`을 다시 확인하고 최신 주차가 맨 앞에 표시되도록 한다.

## 실패 처리

- Drive 폴더를 찾지 못하면 폴더 부재라고 보고하고 추정 가격으로 대체하지 않는다.
- GitHub 푸시가 막히면 편집된 파일/패치를 제공하되 배포 완료라고 말하지 않는다.
- 배포 워크플로가 실패하면 해당 실행 결과를 알리고 원인을 확인한다.
- DB 저장이 불가하면 GitHub에 반영된 것과 Sheets에 저장되지 않은 것을 명확히 구분한다.
